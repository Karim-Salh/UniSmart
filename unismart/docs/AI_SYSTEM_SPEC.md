# UniSmart – نظام المساعد الأكاديمي متعدد الوكلاء (مواصفات)

## 1. قيد التصميم
كل شيء يعمل داخل المشروع بلا API خارجي: تضمينات محلية (`multilingual-e5-small`، 384 بُعدًا) + pgvector + منطق حتمي.
توليد النص الحر اختياري عبر واجهة `LLMProvider` محلية (مثل Ollama) ولا يُفعَّل افتراضيًا؛ الإجابات الافتراضية **اقتباسية** (لا هلوسة).

## 2. المعمارية
```
واجهة React ──► POST /api/ai/v2/chat ──► Orchestrator
                                          ├─ Tone Manager (اكتشاف اللهجة، قوالب النبرة)
                                          ├─ Bylaws Agent  → rag.py  → pgvector (doc_chunks)
                                          ├─ Advisor Agent → advisor.py → rules.py + DB
                                          ├─ Faculty Co-Pilot → copilot.py (مسودات + تحليلات)
                                          └─ General → assistant.py (محرك النوايا الحالي)
كل وكيل يعمل بهوية المستخدم (JWT) وصلاحياته؛ لا وصول مباشر للنموذج إلى قاعدة البيانات.
```
| الوكيل | الأدوار | المهمة |
|---|---|---|
| Bylaws | طالب/دكتور/إدارة | لوائح، تقدير، حضور، إداريات، مع مصادر |
| Advisor | طالب | تقدم، ترشيح مواد، تعارض، عبء |
| Co-Pilot | دكتور (موادّه فقط) | مسودات أسئلة/واجبات، تحليلات |
| General | الكل | بقية الخدمات (جدول، درجات، تسجيل بتأكيد) |

## 3. RAG للوائح
1. **الرفع** (إدارة): PDF/DOCX/TXT ← استخراج نص ← تقطيع حسب «المادة N» (≈900 حرف + تداخل) ← تضمين ← `doc_chunks`.
2. **البحث الهجين**: `0.8·cosine + 0.2·ts_rank`، فلترة بنوع الوثيقة والنسخة الفعّالة (`status='ACTIVE'`).
3. **الامتناع**: إن كانت أعلى درجة < `MIN_SIM` (0.80، تُضبط بمجموعة تقييم) يُرد: «لا أملك معلومات مؤكدة».
4. **التوثيق**: كل إجابة تحمل `citations[{doc, version, article, page, excerpt, score}]`.
5. **الحوكمة**: نسخ متعددة للوثيقة، تفعيل/أرشفة، سجل تدقيق لكل رفع.

### 3.1 «تدريب» المرشد على بيانات الإدارة
"التدريب" هنا **فهرسة واسترجاع** وليس ضبطًا دقيقًا للنموذج؛ فالحقائق المتغيرة (رسوم، مواعيد، لوائح) يجب أن تُحدَّث فورًا وتُنسب لمصدرها.
- **المدخلات** (لوحة الإدارة): نص، `.docx`، `.xlsx`، `.csv`، `.sql`، `.txt/.md`.
- **الجداول** (Excel/CSV/SQL): كل صف يصبح سجلًا `col: value | …` مع `meta{table, cols, vals}` فيجيب المرشد بالأعمدة المسؤول عنها.
- **SQL**: يُقرأ فقط (`CREATE TABLE`/`INSERT`) ولا يُنفَّذ أي أمر؛ الأوامر الأخرى تُتجاهل ويُبلَّغ عددها.
- **الحوكمة**: تفعيل/إيقاف/حذف لكل مصدر، وسجل تدقيق `KNOWLEDGE_ADDED`، واختبار إجابة قبل الاعتماد.
- **الأولوية عند الإجابة**: بيانات النظام الحية أولًا (تسجيل، جدول، درجات)، ثم قاعدة المعرفة بمصدرها، وإلا امتناع صريح.
- ملاحظة: البحث في نسخة الواجهة معجمي (BM25)؛ نسخة الخادم دلالية متعددة اللغات (pgvector) وتفهم السؤال بلغة والمصدر بأخرى.

## 4. وكيل الإرشاد الاستباقي
- **الدرجة**: `0.45·فتحه لمواد لاحقة + 0.35·توافق الصعوبة مع GPA + 0.20·تفضيل المواعيد`، تحت سقف ساعات مسموح (GPA≥3: 18، ≥2: 15، وإلا 12).
- **الصعوبة التاريخية** = `4 − متوسط درجات من أنهوا المادة`.
- **قبل التسجيل (`preflight`)**: تعارض مواعيد، متطلبات ناقصة، عبء ثقيل (تجاوز السقف، مواد صعبة مجتمعة).
- **استباقي**: يُستدعى تلقائيًا عند تغيّر السلة، ويظهر تحذير قبل زر التأكيد.

## 5. المساعد المشترك للدكتور
- **توليد**: موضوع أو PDF/PPTX ← مصطلحات رئيسية ← أسئلة متعددة الخيارات/صح-خطأ ← **مسودات** (`question_drafts`) ← مراجعة ← اعتماد.
- **التحليلات**: لكل سؤال: نسبة الصواب، التمييز (أعلى/أدنى 27%)، أشهر إجابة خاطئة؛ ولكل موضوع: درجة الإتقان؛ وتنبيه للأسئلة المعيبة.
- ترقية الجودة لاحقًا: تفعيل `LLMProvider` محلي لصياغة أفضل مع بقاء الاعتماد البشري إلزاميًا.

## 6. مدير اللهجة والنبرة
- كشف: فصحى، مصري، خليجي، شامي، مغاربي، إنجليزي، فرانكو (قواميس علامات + نسبة الحروف + أرقام الفرانكو).
- النبرة موحدة: **ودودة رسمية**؛ المحتوى الأكاديمي لا يتغير، فقط الصياغة. لهجة بلا قالب تُخدم بالفصحى المبسطة.

## 6.1 طبقة معالجة اللغة الطبيعية (NLP) في الواجهة
تطبيع (همزات/ياء/تشكيل/فرانكو) ← تقطيع وحذف كلمات الحشو ← جذع خفيف (سوابق/لواحق/ضمائر) ← **مفاهيم مترادفة** (صنعك/برمجك/عملك/who made you = `c_make`) ← تصنيف النية بتشابه جيب التمام (TF-IDF) مقابل أمثلة صياغات متعددة ← تصحيح أخطاء الكتابة (Levenshtein) ← استخراج الكيانات (مادة، عدد، موعد) ← ذاكرة السياق. النية المعلوماتية تُعاد صياغتها إلى أمر قياسي فتمر بنفس منطق بيانات النظام. أسئلة الهوية (من صنعك، اسمك، خصوصية بياناتك) تُجاب جاهزة أو من قاعدة المعرفة إن أضافتها الإدارة. لا تُعرض مصادر الإجابة للمستخدم؛ تظهر فقط في «اختبار الإجابة» للإدارة. تنسيق «س: … ج: …» في قاعدة المعرفة يجعل أي صياغة للسؤال تصل للجواب نفسه.

### 6.2 عرض المحتوى الإنجليزي بالعربية
ترجمة **معجمية بالعبارات** داخل المشروع (قاموس مصطلحات قابل للتوسعة من لوحة الإدارة، بدون خدمة خارجية): أطول عبارة مطابقة أولًا، مع الأرقام والعملات. تُفهرس النسختان العربية والإنجليزية فيجد السؤال العربي محتوى إنجليزيًا وبالعكس. إن قلّت تغطية القاموس لجملة (<50%) تُعرض بأصلها. هذه ليست ترجمة آلية عصبية؛ للجودة الأعلى يمكن لاحقًا تركيب نموذج ترجمة محلي (مثل Opus-MT).
### 6.3 جودة قراءة الملفات
عناوين الأقسام تُربط بمقاطعها، وجداول Word تُقرأ كسجلات، وتُزال المقاطع المكررة، وتوجد «معاينة كيف قرأ المرشد الملف» في لوحة الإدارة. تنسيق «س: … ج: …» يعطي إجابة مباشرة لأي صياغة للسؤال.

## 6.4 المرشد الذكي v2 (تخطيط المذاكرة والتعلّم)
- **فصل البيانات**: معرفة عامة (المواد، اللوائح، المواعيد، المحتوى المرفوع من الإدارة) ← تُسترجَع بالـ RAG؛ بيانات خاصة بالطالب (الدرجات، الحضور، الأداء) ← تُقرأ فقط عبر سياق الطالب الحالي (JWT) ولا توجد أداة تأخذ هوية طالب آخر.
- **تحليل السياق**: مواد الطالب + درجاته + نقاط ضعفه + الاختبارات القادمة + الواجبات ← توصية مخصصة، وخطة مذاكرة يومية بحد أقصى 4 ساعات/يوم مع تأجيل صريح لما لا يتسع له الوقت.
- **مساعد التعلّم**: شرح مفاهيم، أسئلة تدريبية بتلميحات وشرح للإجابات الخاطئة. **لا يحل اختبارًا رسميًا**؛ طلبات الحل تُرفض بسبب النزاهة الأكاديمية، ولا يتوفر المرشد أصلًا أثناء الاختبار (التنقل مقفل).
- **منع الهلوسة**: المعلومة الأكاديمية الحساسة من النظام فقط؛ وإلا «لا أملك معلومات مؤكدة».

## 6.5 خط أنابيب التحقق بالوجه
كاميرا ← كشف الوجه ← جودة (حجم، إضاءة، حدّة، زاوية، وجه واحد) ← حيوية (رمش العين EAR + حركة الرأس) ← بصمة 128 ← مقارنة بقالب الهوية ← درجة ثقة ← عتبة ← إجراء (حضور/دخول اختبار). أكثر من وجه ← لا تسجيل. البصمات تُشفَّر (Fernet) والصور لا تُخزَّن إلا الصورة الشخصية المرجعية. الحيوية بالرمش/الحركة تمنع الصور الثابتة لكنها لا تمنع فيديو مُعاد؛ لذلك القرارات الحاسمة تُراجَع بشريًا.

## 7. رصد الوجه في الاختبار (بطلب المنتج)
- غياب الوجه **180 ثانية متواصلة** ← إغلاق الاختبار (تسليم تلقائي بوسم `PROCTOR_TERMINATED`).
- عدم مطابقة الوجه لصاحب الحساب (مسافة > 0.6) في **4 قراءات متتالية** ← إغلاق.
- **مرجع الهوية = الصورة الشخصية** المسجّلة للطالب (يضيفها مرة واحدة ثم تُقفل؛ التغيير/الحذف للإدارة فقط عبر `PUT/DELETE /api/admin/students/{id}/photo` مع سجل تدقيق). `POST /api/students/me/photo` يرفض أي محاولة ثانية بـ 403.
- فقدان الكاميرا يُعامل كغياب. تحذير بعد 30 ثانية.
- **الخصوصية**: لا صور تُخزَّن؛ بصمة رقمية فقط، بموافقة صريحة، مدة احتفاظ، وحذف بطلب الطالب. الإغلاق التلقائي إشارة تُحال لمراجعة بشرية وتظلّم، وليست إثبات مخالفة.
- **قيد**: المطابقة على جهاز الطالب قابلة للتحايل؛ للاختبارات عالية الأهمية أرسل إطارات مصغّرة مشفّرة للتحقق على الخادم بموافقة وسياسة قانونية.

## 8. واجهات الـ API
| الطريقة والمسار | الدور | الطلب | الاستجابة |
|---|---|---|---|
| `POST /api/ai/v2/chat` | الكل | `{message}` | `{reply, agent, dialect, citations[], suggestions[], pending, trace_id, latency_ms}` |
| `POST /api/ai/bylaws/ask` | الكل | `{query, doc_type?}` | `{answer, citations[], confidence, abstained}` |
| `POST /api/ai/bylaws/search` | الكل | `{query, k, doc_type?}` | `{hits[]}` |
| `POST /api/admin/knowledge` (multipart) | إدارة | `title, text_body? أو file (docx/xlsx/csv/sql/txt)` | `202 {source_id, chunks, ignored_sql_statements}` |
| `GET/PATCH/DELETE /api/admin/knowledge[/{id}]` | إدارة | `active` للتفعيل | قائمة المصادر / تأكيد |
| `GET /api/advisor/snapshot` | طالب | – | `{gpa, credits_earned, active[], history{}}` |
| `GET /api/advisor/recommendations?max_credits&prefer_hours` | طالب | – | `{gpa, max_credits, projected_load, recommendations[]}` |
| `POST /api/advisor/preflight` | طالب | `{course_ids[]}` | `{conflicts[], workload{level,reasons[]}, prereq_issues[]}` |
| `POST /api/copilot/quizzes/generate` (multipart) | دكتور | `course_id, topic?, n, file?` | `{drafts[]}` (حالة DRAFT) |
| `GET /api/copilot/exams/{id}/analytics` | دكتور/إدارة | – | `{students, avg_score, weak_topics[], mastery[], questions[]}` |

**أخطاء**: `401` غير مصرّح، `403` خارج الصلاحية، `409` قاعدة أكاديمية، `422` مدخلات غير كافية. لا تُعرض تفاصيل تقنية للمستخدم.

## 9. المراقبة والتقييم
`ai_runs` (الوكيل، اللهجة، الامتناع، الزمن). مجموعة تقييم: 100 سؤال لوائح بإجابات مرجعية لضبط `MIN_SIM`، واختبارات صلاحيات (طالب يسأل عن غيره)، وقياس دقة اللهجات.
