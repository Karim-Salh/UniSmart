# UniSmart – نظام الجامعة الذكي

```
frontend/   الواجهة v2: صفحات رفيعة (login, home, courses, schedule, grades, attend, assign, quiz, chat, notif, settings + صفحات الدكتور والإدارة)
            تشترك في assets/app.js و assets/style.css (انظر docs/DESIGN_SYSTEM.md)
backend/    FastAPI: المصادقة، التسجيل، الاختبارات الآمنة، المساعد الذكي
database/   schema.sql (PostgreSQL)
```

## التشغيل
```bash
cp .env.example .env        # غيّر JWT_SECRET
docker compose up --build   # الواجهة :5173  والـ API :8000/docs
docker compose exec backend python -m app.seed
```
حسابات تجريبية (كلمة المرور 1234): `20240001` طالب · `dr.ahmed` دكتور · `admin` إدارة.

## المبادئ
- الخادم هو المرجع: قواعد التسجيل (`rules.py`) وعدّاد المخالفات والمؤقت.
- المرشد الأكاديمي (`backend/app/assistant.py`) محرك فهم لغة داخل المشروع بدون أي خدمة خارجية: يفهم اللهجات والفرانكو والإنجليزية، وهوية الطالب من JWT، والتسجيل/الحذف يحتاجان تأكيدًا، والمحادثة لا تُخزَّن على الخادم.
- أحداث الاختبار إشارات للمراجعة وليست دليلًا تلقائيًا على الغش.

## قبل الإنتاج
HTTPS، Rate limiting على /auth و/ai، Alembic بدل create_all، تخزين PENDING في Redis، سياسة خصوصية للكاميرا، اختبارات pytest، ربط الواجهة بالـ API.

## الذكاء الاصطناعي
انظر `docs/AI_SYSTEM_SPEC.md` (المعمارية وواجهات الـ API)، و`database/pgvector.sql`، و`backend/app/ai/`، وخطافات React في `frontend-react/src/ai/`. الرصد بالكاميرا يحتاج نماذج الوجه الموجودة في `frontend/assets/models` (تعمل عبر http/https فقط).

## الكاميرا والتعرف على الوجه
نماذج الوجه مدمجة كسكربت (`assets/models/models.js`) فتعمل حتى لو فُتحت الصفحة مباشرة من الملف. والأفضل تشغيلها عبر خادم: `cd frontend && python3 -m http.server 8080` ثم افتح `http://localhost:8080/camera-test.html` لاختبار الكاميرا ونماذج الوجه خطوة بخطوة، وبعدها `login.html`. الكاميرا تحتاج https أو localhost وإذن المتصفح.

نموذج الرؤية الحاسوبية للتحقق من الهوية موصوف في `vision/README.md`.

## تحديث: ربط الواجهة بالـ API + مرشد محلي (بدون أي API خارجي)

**وضعان تلقائيان**: عند تسجيل الدخول تفحص `assets/api.js` الخادم (`/api/health`). إن وُجد → الوضع الحي (دخول JWT، لوحة الطالب، الدرجات، الجدول، الواجبات، الإشعارات، التسجيل، المرشد، الحضور بالوجه كلها من الـ API). وإلا → الوضع التجريبي كما كان بالبيانات داخل المتصفح.

**التشغيل الكامل**: `docker compose up --build` ثم `docker compose exec backend python -m app.seed`، وافتح http://localhost:5173 (nginx يوجّه `/api` للـ backend). حسابات التجربة: `20240001` / `20240002` / `dr.ahmed` / `admin` وكلمة المرور `1234`.

**المرشد الذكي** (`backend/app/ai/guide.py` + `knowledge.py`): محلي بالكامل. يقرأ بيانات الطالب بهويته من JWT فقط (لا مسار يقبل طالبًا آخر)، يحلل الدرجات والحضور والاختبارات والواجبات، يبني خطط مذاكرة، يكشف المواد الأضعف، يولّد أسئلة تدريب بتلميحات وشرح، ويرفض حل الاختبارات الرسمية أو المساعدة أثناء محاولة اختبار جارية. إن لم يجد معلومة يقول ذلك صراحة. لإضافة موضوع تعليمي: أضِف مدخلًا في `TOPICS` واربطه بالمادة في `COURSE_TOPICS`.

**الوجه**: القرار صار على الخادم (`/api/attendance/face/challenge` ثم `/verify`): يقارن البصمة المخزّنة مشفّرةً مع بصمة الجلسة، ويشترط nonce لمرة واحدة. المسار القديم `/api/attendance/face` يُرفض (426) لمن لديه بصمة مسجّلة. تحدّي الرمش/حركة الرأس يُحسب على المتصفح، وهو غير كافٍ وحده ضد الهجمات المتقدمة؛ للإنتاج أضف نموذج anti-spoofing على الخادم.

**الأمان**: تحديد معدل الطلبات، قفل الدخول بعد 5 محاولات فاشلة لمدة 5 دقائق، مهلة للتأكيدات المعلّقة، سجل تدقيق لفشل الدخول والتحقق.

**الاختبارات**: `cd backend && pytest -q` (24 اختبارًا: الأدوار، عزل الطلاب، التسجيل، المرشد، الوجه، القفل).

**ما لم يُربط بعد**: محرك الكويز الآمن في الواجهة ما زال يعمل محليًا (الـ API جاهز له: `/api/exams/*`)، ولوحتا الدكتور والإدارة تعرضان إحصاءات تجريبية عدا السجل والإشعارات وإدارة الصور والتحكم في التسجيل.
